# Баланс жизни

Персональное приложение для ведения дневника питания, здоровья, воды, сна, настроения, привычек и самочувствия. Проект помогает фиксировать ежедневные показатели, смотреть историю и использовать персональные рекомендации.

## Технологии

- React
- TanStack Router / TanStack Start
- Vite
- Supabase
- Tailwind CSS

## Запуск

1. Установите зависимости:

```bash
npm install
```

2. Создайте локальный файл окружения на основе `.env.example` и заполните значения переменных:

```bash
cp .env.example .env
```

3. Запустите приложение в режиме разработки:

```bash
npm run dev
```

4. Для проверки production-сборки выполните:

```bash
npm run build
```

## Доступные команды

- `npm run dev` - запуск локального сервера разработки.
- `npm run build` - production-сборка.
- `npm run build:dev` - сборка в development-режиме.
- `npm run preview` - предпросмотр собранного приложения.
- `npm run lint` - проверка ESLint.
- `npm run format` - форматирование Prettier.

## Переменные окружения

Проект использует переменные окружения для Supabase и серверных AI-функций. Ниже перечислены только названия переменных, без значений и секретов:

- `SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `VITE_SUPABASE_PUBLISHABLE_KEY`
- `VITE_SUPABASE_URL`
- `YANDEX_CLOUD_API_KEY`
- `YANDEX_CLOUD_FOLDER_ID`
- `YANDEX_AI_MODEL`

Не коммитьте реальные значения ключей и токенов в репозиторий.

## Удаление аккаунта

В разделе «Профиль» пользователь может подтвердить необратимое удаление аккаунта
и всех связанных данных. Серверная POST-функция проверяет токен текущей сессии
через Supabase Auth и получает ID пользователя только из ответа Auth. Клиент
передаёт только подтверждение, а не `user_id`.

Для этой операции обязательны серверные `SUPABASE_URL` и
`SUPABASE_SERVICE_ROLE_KEY`. Задайте ключ в секретах серверного окружения хостинга;
не используйте префикс `VITE_`, не передавайте ключ в браузер и не коммитьте его.
При отсутствии ключа операция отклоняется до обращения к Auth и удаления данных.

Удаление выполняется через `auth.admin.deleteUser` на сервере. В миграциях все
семь пользовательских таблиц (`profiles`, `daily_entries`, `health_entries`,
`habits`, `health_features`, `legal_consents`, `user_recipes`) ссылаются на `auth.users(id)` через
`user_id` с `ON DELETE CASCADE`. Поэтому данные и юридические согласия удаляются
каскадно вместе с учётной записью. Перед удалением Auth сервер также удаляет
фотографии личных рецептов из закрытого Storage bucket. Если очистка фотографий
не удалась, удаление аккаунта останавливается с ошибкой.
Убедитесь, что миграции применены в целевом Supabase-проекте; для новых
пользовательских таблиц также необходим соответствующий внешний ключ с каскадом.

## Личные рецепты

Для формы «Мои рецепты» примените миграцию
`supabase/migrations/20261008110000_personal_recipes.sql` к целевому проекту Supabase
до публикации обновлённого приложения. Она создаёт таблицу с RLS и закрытый bucket
`personal-recipe-photos` с ограничением 5 МБ на фото. Рецепты видит и изменяет
только владелец. Они не включены в общий каталог и AI-подбор.

После успеха приложение очищает локальную сессию и сохранённые локальные данные
и открывает экран входа. Восстановить удалённый аккаунт и данные нельзя.
