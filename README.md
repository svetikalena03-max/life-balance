# Баланс жизни

Персональное приложение для ведения дневника питания, здоровья, воды, сна, настроения, привычек и самочувствия. Проект помогает фиксировать ежедневные показатели, смотреть историю и использовать персональные рекомендации.

## Технологии

- React
- TanStack Router / TanStack Start
- Vite
- Supabase
- Tailwind CSS

## Запуск

1. Установите зависимости:

```bash
npm install
```

2. Создайте локальный файл окружения на основе `.env.example` и заполните значения переменных:

```bash
cp .env.example .env
```

3. Запустите приложение в режиме разработки:

```bash
npm run dev
```

4. Для проверки production-сборки выполните:

```bash
npm run build
```

## Доступные команды

- `npm run dev` - запуск локального сервера разработки.
- `npm run build` - production-сборка.
- `npm run build:dev` - сборка в development-режиме.
- `npm run preview` - предпросмотр собранного приложения.
- `npm run lint` - проверка ESLint.
- `npm run format` - форматирование Prettier.

## Переменные окружения

Проект использует переменные окружения для Supabase и серверных AI-функций. Ниже перечислены только названия переменных, без значений и секретов:

- `SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `VITE_SUPABASE_PUBLISHABLE_KEY`
- `VITE_SUPABASE_URL`
- `YANDEX_CLOUD_API_KEY`
- `YANDEX_CLOUD_FOLDER_ID`
- `YANDEX_AI_MODEL`

Не коммитьте реальные значения ключей и токенов в репозиторий.

## Удаление аккаунта

В разделе «Профиль» пользователь может подтвердить необратимое удаление аккаунта
и всех связанных данных. Серверная POST-функция проверяет токен текущей сессии
через Supabase Auth и получает ID пользователя только из ответа Auth. Клиент
передаёт только подтверждение, а не `user_id`.

Для этой операции обязательны серверные `SUPABASE_URL` и
`SUPABASE_SERVICE_ROLE_KEY`. Задайте ключ в секретах серверного окружения хостинга;
не используйте префикс `VITE_`, не передавайте ключ в браузер и не коммитьте его.
При отсутствии ключа операция отклоняется до обращения к Auth и удаления данных.

Удаление выполняется через `auth.admin.deleteUser` на сервере. В миграциях все
семь пользовательских таблиц (`profiles`, `daily_entries`, `health_entries`,
`habits`, `health_features`, `legal_consents`, `user_recipes`) ссылаются на `auth.users(id)` через
`user_id` с `ON DELETE CASCADE`. Поэтому данные и юридические согласия удаляются
каскадно вместе с учётной записью. Перед удалением Auth сервер также удаляет
фотографии личных рецептов из закрытого Storage bucket. Если очистка фотографий
не удалась, удаление аккаунта останавливается с ошибкой.
Убедитесь, что миграции применены в целевом Supabase-проекте; для новых
пользовательских таблиц также необходим соответствующий внешний ключ с каскадом.

## Личные рецепты

Для формы «Мои рецепты» примените миграцию
`supabase/migrations/20261008110000_personal_recipes.sql` к целевому проекту Supabase
до публикации обновлённого приложения. Она создаёт таблицу с RLS и закрытый bucket
`personal-recipe-photos` с ограничением 5 МБ на фото. Рецепты видит и изменяет
только владелец. Они не включены в общий каталог и AI-подбор.

После успеха приложение очищает локальную сессию и сохранённые локальные данные
и открывает экран входа. Восстановить удалённый аккаунт и данные нельзя.

## Дневник сахара крови

Перед публикацией экрана «Здоровье → Сахар крови» примените миграцию
`supabase/migrations/20261008150000_glucose_readings.sql` в целевом Supabase.
Измерения (ммоль/л, дата и время, связь с приёмом пищи, примечание) сохраняются
в отдельной таблице с RLS только для владельца и удаляются вместе с аккаунтом.
Экран позволяет записывать несколько измерений в день, исправлять записи и
выгружать последние 500 в CSV для самостоятельной передачи врачу. Автоматической
диагностики, порогов нормы и прямого доступа врача к данным нет.

При отмеченной беременности или подтверждённом тромбе готовые тренировки не
показываются. При беременности AI-подбор рецептов также отключён, поскольку
каталог не проверен как индивидуальный план питания в этой ситуации.


## Дневник беременности

Раздел «Здоровье → Беременность» хранит предполагаемую дату родов, приблизительный срок, вес, давление, самочувствие, визиты и рекомендации врача. CSV содержит последние 500 записей. Записи отдельны от общего дневника; автоматического назначения лечения, оценки показателей, уведомлений и доступа врача нет.

Перед выпуском примените `supabase/migrations/20261010180000_pregnancy_diary.sql`. Две таблицы закрыты RLS по user_id и удаляются с аккаунтом через каскад. Для ограничений тренировок и AI-подбора рецептов отметка беременности в особенностях здоровья остаётся источником состояния.

## Семейная группа

Примените миграцию `supabase/migrations/20261008140000_family_access.sql` до
публикации экрана «Семья». Организатор создаёт группу и одноразовые коды
приглашения сроком на 7 дней. Приглашённый регистрирует собственный аккаунт,
заполняет профиль и вводит код в разделе «Семья». Организатор может исключить
участника или расформировать группу, а участник может выйти самостоятельно.
При этом аккаунты, дневники и сведения о здоровье участников не удаляются и
не становятся доступны другим членам группы. Миграция не меняет RLS этих таблиц.

Это только семейная группа: платный тариф, пробный период, право на бесплатное
пользование и платежи пока не подключены. Нельзя обозначать её как действующую
семейную подписку до появления серверной проверки доступа и оплаты.

## Совместная проверка здоровья и семьи

Ветка объединяет дневники беременности и сахара с семейной группой. При смене
аккаунта формы, приглашения и загруженные медицинские записи сбрасываются.
Ошибки сохранения особенностей здоровья не снимают ранее сохранённые ограничения.
AI-подбор рецептов получает полный список заболеваний, включая диабет и варикоз,
а не сокращённую подпись профиля. Готовые тренировки также скрыты при отметках
«только ходьба» и «только ЛФК»; до загрузки ограничений запуск недоступен.

Локальные регрессионные проверки:

```bash
node --test tests/registration.test.mjs tests/health-profile.test.mjs scripts/pregnancy.test.ts
npx tsc --noEmit
npm run build
```

До выпуска нужны три миграции, перечисленные выше, и проверка изоляции в
целевой Supabase на двух тестовых аккаунтах. Локальные тесты с подменённым
клиентом не подтверждают применение миграций или работу RLS в живой базе.
